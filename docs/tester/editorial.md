# Editorial Review

## Main Goals

The main goals of this stage are:
- Check that the editorial correctly explains the intended solution.
- Check that the correctness proof and complexity analysis are valid.
- Report any unclear, incorrect, or missing explanation to the setter.

::: info Checklist for this stage
- Read the editorial in the shared Overleaf document.
- Compare it with the final statement and intended solution.
- Send any issues to the setter.
:::

## Reviewing the Editorial

Read the editorial after you have independently solved and tested the problem.

Check that:

- the key idea and intuition are explained clearly;
- the described algorithm is correct;
- the correctness proof is rigorous;
- the stated time complexity is correct;
- important implementation details are included when needed;
- subtask solutions are explained when they give useful insight toward the full solution.

The editorial should match the final version of the statement. In particular, check that it does not rely on assumptions or constraints that are missing from the statement.

::: tip Focus on correctness before style
The most important goal is that the editorial teaches the correct solution. Wording and presentation improvements are useful, but they are secondary to correctness and clarity.
:::

## Reporting Issues

When you find an issue, report the exact part of the editorial and explain why it is incorrect or unclear. If a proof step is missing, point out which claim needs justification.

::: warning Recheck after important changes
If the statement, intended solution, or editorial changes substantially, recheck the affected parts of the editorial.
:::

## Before Moving On

::: tip Ready to move on when
- The editorial clearly explains the intended solution.
- The correctness proof is valid.
- The stated complexity is correct.
- The editorial is consistent with the final statement.
- All important issues have been fixed and rechecked.
:::
